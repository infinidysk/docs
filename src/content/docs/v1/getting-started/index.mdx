1.x is the stable release and gets bug fixes only. These pages describe the latest 1.x release. A <a class="since" href="https://github.com/infinidysk/infinidysk/releases/tag/v0.8.0">since 0.8.0</a> pill marks something that needs at least that version; check yours under **Settings → Support**.

## Prerequisites

1. **Usenet provider** — NNTP host, credentials, and connection allowance.
2. **Indexers** (optional for first play) — Newznab-compatible sources for search and Arr.
3. **Docker** — Engine + Compose v2. Symlink imports also need Linux FUSE (`/dev/fuse`).

## Where to run it

- **Docker** (recommended): you run Compose, Unraid or similar and wire Arr apps and rclone yourself. See [Run with Docker](/v1/getting-started/docker/).
- **Prebuilt Linux archives**: run without Docker. See [Prebuilt Linux archives](/v1/getting-started/prebuilt-archives/).
- **[DUMB](https://dumbarr.com/)**: infinidysk is a supported core module with guided onboarding. Use [DUMB's infinidysk guide](https://dumbarr.com/services/core/nzbdav/) for its paths and ports, and this site for Settings and troubleshooting.

## Release channels and tags

Docker images and [prebuilt Linux archives](/v1/getting-started/prebuilt-archives/) follow the same release train. Choose a tag based on how much change you want to absorb:

| Tag | What it is |
|-----|------------|
| `latest` | The current stable release. Recommended for most installs. |
| `lts` | A stable release promoted by hand, usually behind `latest`. Docker image tag only. |
| `rc` | Release candidate for the next version, promoted from `dev` after basic regression testing. Published to `ghcr.io/infinidysk/infinidysk` only. |
| `dev` | Work-in-progress snapshots. Frequent and sometimes broken; testing only. The tag rolls, and `version.txt` in each build carries its timestamped version. Published to `ghcr.io` and Docker Hub. |

For reproducible deployments, pin an exact version tag (`v1.2.3`) or a rolling minor/major alias (`v1.2`, `v1`). Versioned `v*-rc.*` pre-releases and image tags are removed when the stable release ships; the rolling `rc` and `dev` tags persist.

Running from source is a development workflow (see [Contributing](/v1/community/contributing/)), not a supported install. Releases are tested as the Docker image and the prebuilt archives.
