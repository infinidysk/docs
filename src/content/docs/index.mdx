## How it works

Sonarr, Radarr and other Arr instances add infinidysk as a SABnzbd download client. Instead of downloading a release, infinidysk reads the NZB and shows its files on a mount. When your media server plays a file, infinidysk fetches only the articles it needs from your Usenet providers.

	<div class="flow-node flow-arr"><strong>Sonarr, Radarr</strong><span>Arr instances</span></div>
	<div class="flow-edge flow-e1"><span>SABnzbd API</span></div>

## What changes in 2.x

Both versions speak the same SABnzbd API and serve the same WebDAV paths, so Arrs and media servers see no difference. Both have:

<ul class="shared">
	<li>SABnzbd API for Arrs</li>
	<li>WebDAV</li>
	<li>Symlink and STRM imports</li>
	<li>Health checks and Arr replacement</li>
	<li>Multiple providers with priority levels</li>
	<li>Download speed limit</li>
	<li>Disk segment cache</li>
	<li>SQLite and PostgreSQL</li>
	<li>Prometheus metrics</li>
</ul>

What differs:

| Feature | 1.x | 2.x |
|---|---|---|
| Mount | rclone sidecar | Built-in FUSE |
| Provider catalog with backbones | <span class="no">No</span> | Yes |
| Imports a 1.x config | <span class="no">—</span> | Yes |
| PAR2 repair | Yes | <span class="no">Not yet</span> |
| Stremio and addon routes | Yes | <span class="no">Not yet</span> |
| Search, indexers and Prowlarr | Yes | <span class="no">Not yet</span> |
| Backup and restore | Yes | <span class="no">Not yet</span> |
| Watchtower, Preflight and Warden | Yes | <span class="no">No</span> |

Sequential throughput is on par within run-to-run variance: 103–111 MB/s on 1.x, 92–103 MB/s on 2.x. Neither version rebuffered in five plays at a 3.1 MB/s playback rate.

<p class="perf-method">Measured on 27 October 2026 with 1.6.3 and 2.0.0-alpha.8 in Docker on one Apple M4 Pro host, one commercial provider with 20 connections, five posts with a median size of 10.7 GB, three passes.</p>
